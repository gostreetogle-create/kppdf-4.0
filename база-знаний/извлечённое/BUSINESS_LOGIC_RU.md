# Бизнес-логика — CRM/PLM «СпортИН-ЮГ» (kppdf-4.0)

> **Версия:** 4.0 · 2026-06-06
> **Назначение:** Единый компас развития. Вся бизнес-логика: что сделано, что строим, какие данные нужны.
> **Как читать:** Сверху вниз — от общего к деталям. Сначала модули, потом данные, потом процессы.
> **Железное правило:** Если новая фича не вписывается — остановиться и перепроверить.

## 0. АРХИТЕКТУРНЫЕ ПРИНЦИПЫ (не нарушать)

```
┌──────────────────────────────────────────────────────────────┐
│  Модульная архитектура — каждый модуль подключается          │
│  независимо, не ломая существующее                           │
│                                                              │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐    │
│  │ Продажи  │  │Производ. │  │  Склад   │  │Бухгалтер.│    │
│  │ (Фаза 1) │→ │ (Фаза 2) │→ │ (Фаза 3) │→ │ (Фаза 4) │    │
│  └──────────┘  └──────────┘  └──────────┘  └──────────┘    │
│         ↓              ↓             ↓            ↓         │
│  ┌──────────────────────────────────────────────────────┐   │
│  │          0. ЯДРО (Конструктор документов +           │   │
│  │                 UI Kit + Инфраструктура)              │   │
│  └──────────────────────────────────────────────────────┘   │
└──────────────────────────────────────────────────────────────┘
```

### 1. Неизменяемость истории (Snapshot-модель)
- **Товар в КП/Заказе — это снимок.** При создании КП данные товара копируются в документ.
- Редактирование справочника товаров НЕ меняет уже созданные КП и заказы.
- В заказе хранятся: название, артикул, характеристики, количество — **без цен** (цены — только в КП).

### 2. Модульность
- Каждый модуль (Продажи, Производство, Склад, Бухгалтерия) — независимый.
- Можно добавить модуль, не трогая остальные.
- Модули общаются через общие справочники (Контрагенты, Товары).
- Если модуль отключён — его пункты меню скрыты.

### 3. Безопасный деплой
- Обновления только ДОБАВЛЯЮТ новые таблицы/колонки.
- Существующие данные НЕ удаляются и НЕ перезаписываются.
- Фотографии, файлы, документы — в отдельном хранилище (не в БД).

### 4. Контекстная навигация
- При переходе в другой раздел для создания/редактирования — после завершения возврат в исходную точку.
- Никаких «вы потеряли введённые данные».

### 5. Роли и задачи
- У каждой задачи (Task) есть роль/исполнитель.
- Нет задачи без ответственного.
- Недостающие данные формируют автоматические задачи для конкретных отделов.

## III. СТРУКТУРА ТОВАРА (детально)

### 🏪 Товар — что это?

Товар — это **единица, которую продаём**. Она может быть двух типов:

```
ТОВАР
├── 🛒 Покупной (товар закупается у поставщика)
│   └── Просто: заказали → получили → отгрузили
│
└── 🔧 Изготавливаемый (производится на предприятии)
    └── Состоит из КОМПОНЕНТОВ
        ├── Компонент 1
        │   ├── Материалы (металл, краска...)
        │   └── Виды работ (резка → сварка → покраска)
        ├── Компонент 2
        │   ├── Материалы (труба, пластик...)
        │   └── Виды работ (гибка → сварка)
        └── ...
```

### Поля товара (предложение — требует утверждения)

| Поле | Тип | Обязательное | Примечание |
|------|-----|-------------|------------|
| **Наименование** | text | ✅ | Полное название |
| **Артикул (SKU)** | text (unique) | ✅ | Авто: 2 буквы + 4 цифры. Можно вручную |
| **Категория** | FK → categories | ✅ | SP / MF / OG / OS / MB / NV / PR + свои |
| **Тип** | enum | ✅ | Покупной / Изготавливаемый |
| **Описание** | text | — | Характеристики |
| **Базовая цена** | number | ✅ | Из прайс-листа |
| **Наценка по умолчанию** | number | — | % для расчёта КП |
| **Единица измерения** | text | ✅ | шт / комплект / кв.м / м.п / кг |
| **Фотографии** | image[] | — | Одно или несколько фото |
| **Вес (кг)** | number | — | Для доставки |
| **Габариты (ДхШхВ мм)** | text | — | Для доставки |
| **Материал** | text | — | Основной материал |
| **Есть паспорт качества** | boolean | — | ✅ если PDF есть |
| **Есть чертёж** | boolean | — | ✅ если DWG есть |
| **Компоненты** | relation[] | — | Только для изготавливаемых |
| **Активность** | boolean | ✅ | Отображается в витрине |

### Компонент (составляющая часть товара)

| Поле | Тип | Обязательное | Примечание |
|------|-----|-------------|------------|
| **Название** | text | ✅ | Например: «Стойка», «Перекладина», «Сидушка» |
| **Количество на товар** | number | ✅ | Сколько штук этого компонента в товаре |
| **Описание** | text | — | |
| **Чертёж** | file | — | IDW/DWG |
| **Порядок** | number | ✅ | Очерёдность изготовления |
| **Материалы** | relation[] | — | Список материалов с количеством |
| **Виды работ** | relation[] | — | Какие работы и нормо-часы |

### Виды работ (справочник, настраиваемый)

| Поле | Тип | Обязательное | Примечание |
|------|-----|-------------|------------|
| **Название** | text | ✅ | Лазерная резка, Сварка, Покраска... |
| **Отдел** | text | ✅ | Проектирование / Изготовление / Отгрузка |
| **Длительность по умолчанию (часы)** | number | — | Норма времени |
| **Рабочий центр** | FK | — | Станок / пост |
| **Активность** | boolean | ✅ | |

### Конкретные виды работ (из реального производства)

| Вид работы | Отдел | Оборудование |
|-----------|-------|-------------|
| **Лазерная резка** | Изготовление | Станок лазерной резки |
| **Труборез** | Изготовление | Труборезный станок |
| **Полуавтоматическая сварка** | Изготовление | Сварочный полуавтомат |
| **Деревообработка** | Изготовление | Деревообрабатывающий станок |
| **Порошковая покраска** | Изготовление | Камера покраски |
| **Пескоструйная мойка труб** | Подготовка | Пескоструй |
| **Лазерная сварка** | Изготовление | Лазерный сварочный |
| **Обычная сварка** | Изготовление | Сварочный аппарат |
| **Слесарные работы** | Сборка | — |

│                        1. ПРОДАЖИ                                │

│                                  ┌─────────────────┐            │
│                                  │ КОММЕРЧЕСКОЕ    │            │
│                                  │ ПРЕДЛОЖЕНИЕ     │            │
│                                  │ (PDF)           │            │
│                                  └────────┬────────┘            │
│                                           │                     │
│                               ┌───────────┴───────────┐        │
│                               ↓                       ↓        │
│                        ┌──────────┐          ┌──────────────┐  │
│                        │ Клиент   │          │ Клиент       │  │
│                        │ согласен │          │ отказался    │  │
│                        └────┬─────┘          └──────┬───────┘  │
│                             ↓                       ↓          │
│                     ┌──────────────┐          ┌──────────────┐ │
│                     │ ЗАКАЗ        │          │ Архив       │  │
│                     │ (копия без   │          │ (можно       │  │
│                     │  цен)        │          │  переделать) │  │
│                     └──────┬───────┘          └──────────────┘ │
│                            │                                    │
│                            ↓ переход к производству              │
├─────────────────────────────────────────────────────────────────┤
│                        2. ПРОИЗВОДСТВО                          │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  ┌─────────────────────────────────────────────────────────┐    │
│  │ ЗАКАЗ попадает в производство                            │    │
│  │                                                          │    │
│  │ 1. РАСПРЕДЕЛЕНИЕ по видам работ                          │    │

│  │    - Каждый компонент → список работ                     │    │
│  │    - Каждая работа → срок + ближайший свободный рабочий  │    │
│  │    - Зависимости (что за чем)                            │    │
│  │                                                          │    │
│  │ 3. ЗАДАЧИ для отделов                                    │    │
│  │    - Проектировщик: не хватает данных → задача           │    │
│  │    - Снабженец: нет материала → задача на закупку        │    │
│  │    - Мастер цеха: назначить исполнителя                  │    │
│  │                                                          │    │
│  │ 4. ВЫПОЛНЕНИЕ                                            │    │
│  │    - Рабочий отмечает выполнение работы                  │    │
│  │    - Статус задачи: выполнено                            │    │
│  │    - Когда все компоненты готовы → товар готов           │    │
│  │                                                          │    │
│  │ 5. ПРОВЕРКА КАЧЕСТВА                                     │    │
│  │    - Паспорт качества                                    │    │
│  │    - Сертификат (если требуется)                         │    │
│  └─────────────────────────────────────────────────────────┘    │
│                            ↓                                    │
│                      Готов к отгрузке                            │
├─────────────────────────────────────────────────────────────────┤
│                      3. ОТГРУЗКА                                │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  ┌─────────────────────────────────────────────────────────┐    │
│  │ 1. Выбор шаблона отгрузочных документов                  │    │

## V. НЕИЗМЕНЯЕМОСТЬ ДАННЫХ (Snapshot)

### Как работает:

1. **Редактирование товара** в справочнике → меняется только справочник
2. **Уже созданные КП** хранят СНИМОК (snapshot) товара на момент создания
3. **Заказы** тоже хранят свой снимок (копия из КП, без цен)
4. **Чертежи и паспорта** — файлы, привязанные к товару, не удаляются

### Структура snapshot'а в КП:

```typescript
// В КП хранится не ссылка на товар, а копия нужных полей
interface ProposalItem {
  // Ссылка на исходный товар (для информации)
  sourceProductId: string;

  // Snapshot (копия на момент создания КП)
  productName: string;
  productSku: string;
  productUnit: string;
  productDescription: string;

  // Данные КП
  quantity: number;
  unitPrice: number;
  total: number;
  markupPercent: number;
}

// В ЗАКАЗЕ — похожая структура, но БЕЗ цен
interface OrderItem {
  sourceProductId: string;
  sourceProposalId: string;

  // Snapshot (копия из КП, без цен)
  productName: string;
  productSku: string;
  productUnit: string;
  productDescription: string;

  // Данные заказа
  quantity: number;

  // Статус продвижения
  status: string; // 'pending' | 'in_design' | 'in_production' | 'ready' | 'shipped'
  components: OrderComponentStatus[];
}
```

## IX. СИСТЕМА РОЛЕЙ И ДОСТУПА

### Как устроено

1. **Сотрудник** (Worker/User) — ФИО, телефон, email, должность
2. **Роль** (Role) — набор прав доступа к разделам системы
3. **Разделы** (Sections) — логические группы в меню (Продажи, Производство, Склад...)

### Принцип
- При создании сотрудника → выбирается роль из выпадающего списка
- Администратор настраивает: **какая роль → к каким разделам имеет доступ**
- Настройка — через галочки (чекбоксы) для каждой роли
- Разделы предопределены архитектурой (см. структуру меню)

### Роли (начальные)
| Роль | Доступ по умолчанию |
|------|-------------------|
| **Администратор** | Всё |
| **Менеджер по продажам** | Продажи, Справочники |
| **Руководитель производства** | Производство, Справочники |
| **Мастер цеха** | Производство (кроме настроек) |
| **Рабочий** | Производство (только свои задачи) |
| **Кладовщик** | Склад, Закупки |
| **Бухгалтер** | Бухгалтерия, Отчёты |
| **Наблюдатель** | Только чтение |

## X. ПРОВЕРКА ГОТОВНОСТИ К ПРОИЗВОДСТВУ

Перед тем как товар попадает на диаграмму Ганта, он проходит проверку:

### Статусы готовности товара к производству
```
Новый → На комплектации → Укомплектован → В производстве → Готов
  (только     (проверка:       (менеджер       (на Ганте)    
   создан)     чертежи ✅      подтвердил)
               материалы ✅
               компоненты ✅
               спецификации ✅)
```

### Алгоритм
1. Товар создан, но может не иметь всех данных (нет чертежа, не указаны компоненты...)
2. **Руководитель производства** открывает заказ → видит статус каждого товара
3. Если товар **укомплектован** (все данные есть) → нажимает «Поставить в производство»
4. Товар попадает на диаграмму Ганта, автоматически распределяясь по видам работ
5. Если данных не хватает → **формируется задача** для конкретного отдела:
   - Нет чертежа → задача проектировщику
   - Нет материала → задача снабженцу
   - Нет компонентов → задача инженеру-конструктору
