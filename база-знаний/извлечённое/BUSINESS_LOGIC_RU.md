# Бизнес-логика — Управление производством (CRM/PLM)

> **Версия:** 2.0 · 2026-06-03
> **Что это:** Описание ВСЕХ бизнес-процессов на человеческом языке. Без кода, без технологий — только смысл.
> **Когда понадобится:** после того как ядро готово. Тогда проходим по пунктам и реализуем.

---

## Общая картина

Система ведёт товар от заказа клиента до отгрузки с производства.

```
ЗАКАЗ → ПРОИЗВОДСТВО → СКЛАД → ОТГРУЗКА
(продали)  (сделали)   (храним)  (отправили)
```

На каждом этапе свои сотрудники, свои документы, свои правила.

**Документы** формируются из гибких шаблонов (КП, накладные, акты). Шаблоны настраиваются в разделе «Администрирование».

## Часть 0: КОНСТРУКТОР ДОКУМЕНТОВ (СТАРТОВАЯ)

> 🚧 Это первое, что мы строим в kppdf-4.0. Всё остальное — потом.

### 0.1 Шаблоны таблиц (Table Templates)

**Идея:** Пользователь создаёт шаблон таблицы — выбирает колонки из существующих справочников (Товары, Клиенты…) и сохраняет. Позже этот шаблон вставляется в документ (КП, накладная, акт).

**Как работает:**
1. Захожу в «Администрирование → Шаблоны таблиц»
2. Нажимаю «Создать шаблон»
3. Даю название: «Таблица товаров для КП»
4. Добавляю колонки:
   - Выпадающий список №1: выбираю таблицу-источник (например, «Товары»)
   - Выпадающий список №2: выбираю поле из этой таблицы (например, «Наименование»)
   - Настраиваю ширину, заголовок колонки
5. Добавляю ещё колонки: Артикул, Цена, Количество…
6. Нажимаю «Сохранить»
7. Шаблон появляется в списке — можно редактировать, клонировать, удалить

**Ключевой механизм:**
```
РЕЕСТР ТАБЛИЦ (сервис)
  └─ Товары (products)
  │    ├─ name
  │    ├─ article
  │    ├─ price
  │    └─ category
  └─ Клиенты (clients)
       ├─ name
       ├─ phone
       └─ email

ШАБЛОН ТАБЛИЦЫ (сохранённый)
  ├─ Название: "Таблица товаров для КП"
  ├─ Колонка 1: { table: 'products', field: 'name', label: 'Наименование' }
  ├─ Колонка 2: { table: 'products', field: 'article', label: 'Артикул' }
  └─ Колонка 3: { table: 'products', field: 'price', label: 'Цена' }
```

**Что сохраняется:**
- Название шаблона
- Список колонок (каждая ссылается на таблицу + поле)
- Дата создания/изменения

**Действия:**
- Создать новый шаблон
- Редактировать (изменить название, добавить/убрать колонки, поменять порядок)
- Клонировать (создать копию)
- Удалить

**Статус:** 🚧 В разработке (первый этап kppdf-4.0)

### 0.2 Реестр таблиц (Table Registry)

**Идея:** Централизованный сервис, который знает обо всех таблицах/справочниках в системе. Любой компонент может спросить: «Какие таблицы есть?» → получить список. «Какие поля у таблицы X?» → получить поля.

**Зачем:** Чтобы выпадающие списки в конструкторе таблиц автоматически наполнялись актуальными данными.

**На старте (фронтенд):**
- Фейковый сервис с жёстко зашитым списком таблиц и полей
- Но сделанный через правильные интерфейсы/контракты
- При появлении бэкенда — просто меняем источник данных, интерфейс не меняется

**Статус:** 🚧 В разработке

### 0.3 Контракты (Contracts / Interfaces)

**Идея:** Все структуры данных описываются TypeScript-интерфейсами. Фронтенд работает с этими интерфейсами. Когда появится бэкенд — он реализует те же интерфейсы. Ничего не сломается.

**Ключевые контракты:**
```typescript
// Метаданные таблицы (для реестра)
interface TableMeta {
  name: string;        // 'products' — системное имя
  label: string;       // 'Товары' — человеческое название
  collection: string;  // 'products' — коллекция в MongoDB
  fields: TableField[];
}

// Поле таблицы
interface TableField {
  name: string;   // 'article'
  label: string;  // 'Артикул'
  type: 'string' | 'number' | 'boolean' | 'date';
}

// Сохранённый шаблон таблицы
interface TableTemplate {
  id: string;
  name: string;              // 'Таблица товаров для КП'
  columns: TemplateColumn[];
  createdAt: string;
  updatedAt: string;
}

// Колонка внутри шаблона
interface TemplateColumn {
  tableName: string;   // 'products' — из какой таблицы
  fieldName: string;   // 'price' — какое поле
  label: string;       // 'Цена' — заголовок колонки
  width?: string;      // '120px'
  order: number;       // порядок слева направо
}
```

**Статус:** 🚧 В разработке

### 0.4 Временные таблицы (Mock Data)

**Идея:** На старте нужны реальные справочники, чтобы было из чего выбирать в конструкторе. Создаём две таблицы: Товары и Клиенты.

**Товары (products):**
- Название, артикул, цена, категория, единица измерения

**Клиенты (clients):**
- Название/ФИО, телефон, email, адрес, ИНН, тип (физ/юрлицо)

**Как сделано:** Через сервис-заглушку (MockApiService), который возвращает фейковые данные, но соблюдает контракт `ApiResponse<T>`. Когда появится бэкенд — меняем сервис на реальный.

**Статус:** ✅ Готово (модели созданы в project-core, нужно перенести в kppdf-4.0)

## Часть 1: ПРОДАЖИ

### 1.1 Товары и услуги
Что продаём:
- Название, артикул
- Тип: товар / услуга / работа
- Цена
- Категория (в какой группе лежит)
- Фотографии
- Единица измерения (штуки, метры, килограммы…)
- Характеристики (размеры, материал, цвет…)

### 1.2 Клиенты (контрагенты)
Кому продаём:
- Название организации или ФИО
- ИНН, КПП, банковские реквизиты
- Роль: клиент / поставщик / наша компания / всё вместе
- Контакты (телефон, email, адрес)

### 1.3 Коммерческое предложение (КП)
Документ для клиента:
- Список товаров с ценами
- Условия (сроки, доставка, гарантия)
- Наша компания (реквизиты, логотип, фон бланка)
- Клиент (кому)
- Номер КП, дата

**Статусы КП:**
```
Черновик → Отправлено → Принято
                      → Отклонено → Черновик (новая версия)
```

**Что можно делать:**
- Менять состав (добавить/убрать товары) — только в Черновике
- Менять цены, наценку, скидку
- Скачать PDF (красивый документ)
- Отправить ссылку клиенту (гостевой доступ — без пароля)

### 1.4 Заказы клиентов
Когда клиент согласился:
- Номер заказа
- Какое КП (связь)
- Список позиций с количеством
- Статус заказа (принят → в работе → готов → отгружен)
- Планируемая дата готовности

## Часть 2: ПРОИЗВОДСТВО

### 2.1 Спецификации изделий (BOM)
Из чего состоит изделие:
- Список материалов и их количество
- Список операций (что нужно сделать)
- Чертежи, схемы
- Нормы времени

### 2.2 Технологические операции
Какие шаги нужны для производства:
- Название операции (резка, сварка, покраска…)
- Оборудование
- Норма времени
- Последовательность (что за чем)

### 2.3 Техпроцессы (маршрутные карты)
Полная цепочка операций для изделия:
- Список операций по порядку
- Для каждой: время, оборудование, исполнитель

### 2.4 Наряды на производство
Задание для цеха:
- На какой заказ
- Какое изделие
- Какие операции выполнить
- Кто исполнитель
- Плановая дата
- Статус выполнения

### 2.5 Диаграмма Ганта (план работ)
Визуальное отображение:
- Все заказы на шкале времени
- Кто чем занят
- Что пересекается, что задерживается

---

## Часть 3: СКЛАД

### 3.1 Склады
Где храним:
- Название склада
- Адрес
- Ответственный

### 3.2 Материалы и остатки
Что есть в наличии:
- Какой материал / товар
- В каком количестве
- На каком складе
- Минимальный запас (когда пора заказывать)

### 3.3 Движения склада
Что происходит с материалами:
- Приход (закупили, произвели)
- Расход (отгрузили, списали в производство)
- Перемещение (между складами)
- Резервирование (забронировано под заказ)

### 3.4 Заявки на закупку
Когда материалов не хватает:
- Какой материал нужен
- Сколько
- Для какого заказа
- Кто утверждает

### 3.5 Заказы поставщикам
Когда заявка утверждена:
- У какого поставщика закупаем
- Что, сколько, по какой цене
- Ожидаемая дата поставки

## Часть 4: ОТГРУЗКА

### 4.1 Отгрузки
Когда заказ готов к отправке:
- Какой заказ
- Какие позиции отгружаем
- Дата отгрузки
- Способ доставки

### 4.2 Отгрузочные документы
Что печатаем:
- Товарная накладная
- Счёт-фактура
- Акт выполненных работ
- Транспортная накладная

## Часть 5: СЕБЕСТОИМОСТЬ

### 5.1 Калькуляция (плановая)
Сколько БУДЕТ стоить производство:
- Материалы (по ценам закупки)
- Работа (по нормо-часам)
- Накладные расходы (аренда, электричество…)

### 5.2 Фактические затраты
Сколько РЕАЛЬНО стоило:
- Фактический расход материалов
- Фактическое время работы
- Отклонения от плана

## Часть 6: АДМИНИСТРИРОВАНИЕ

### 6.0 Структура левого меню ( sidebar )

**Группы разделов:**
```
📋 Документы
  ├─ Коммерческие предложения
  ├─ Заказы
  └─ Отгрузки

📦 Справочники
  ├─ Товары и услуги
  ├─ Клиенты
  └─ Поставщики

🏭 Производство
  ├─ Спецификации (BOM)
  ├─ Наряды
  └─ План работ (Гант)

📊 Склад
  ├─ Склады
  ├─ Остатки
  └─ Движения

⚙️ Администрирование
  ├─ Пользователи и роли
  ├─ Шаблоны таблиц      ← то, что мы строим сейчас
  ├─ Шаблоны документов
  ├─ Статусы
  └─ Настройки системы
```

**Статус:** 🚧 Нужно реализовать в kppdf-4.0

### 6.1 Пользователи и роли
Кто работает в системе:
- **Администратор** — всё может
- **Менеджер** — продажи, клиенты, КП
- **Производственник** — наряды, операции
- **Кладовщик** — склад, материалы
- **Наблюдатель** — только смотрит

### 6.2 Настройки системы
Общие параметры:
- Название компании
- Валюта (рубли)
- НДС (сколько процентов)
- Срок действия КП (дней)
- Шаблоны документов (бланки)

### 6.3 Статусы
Гибкая настройка статусов для любой сущности:
- Название статуса (Черновик, В работе, Готово…)
- Цвет метки
- Какие переходы разрешены (из Черновика → можно в Отправлено, нельзя сразу в Готово)
- Какой статус начальный, какой конечный

## Post-Core: Инструменты разработчика / Админ-панель

Эти фичи — следующий этап после того как ядро готово. Они не входят в минимальное ядро, но нужны для удобной работы.

### 1. Универсальная CRUD таблица с выбором полей из БД

**Идея:** Таблица, которая подключается к существующей коллекции MongoDB и автоматически строит колонки по её схеме.

**Статус:** P2 (после этапа 1)

### 2. Текстовый редактор с вставкой таблиц

**Идея:** WYSIWYG редактор (TinyMCE/Quill/PrimeNG Editor), который умеет вставлять сохранённые таблицы как живые блоки.

**Статус:** P3 (после этапа 1)

## Что требует уточнения

По каждому разделу выше есть детальные вопросы. Пройдём когда будем готовы.

Примеры:
- **Товары:** Какие именно характеристики? Размеры, материал, цвет — что ещё?
- **КП:** Какой бланк? Только текст или с фоном? Какие условия прописываем?
- **Производство:** Реальное производство (станки, цеха) или сборка из готового?
- **Склад:** Один склад или несколько? Адресное хранение (стеллаж, полка)?
- **Себестоимость:** Какие накладные расходы учитываем?
