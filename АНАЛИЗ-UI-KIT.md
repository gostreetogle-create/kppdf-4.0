## СРАВНЕНИЕ ДВУХ ПРОМПТОВ

### Промпт 1: «Principal Design Systems Architect»
**Фокус:** дизайн-системный уровень — токены, шкалы, системность
**Сильные стороны:** 
- Глубокий охват foundations (color, typography, spacing, shadows, radius, motion)
- Акцент на консистентность
- Русский язык и его особенности
- Предлагает создать «стратегию» — какое ощущение должен вызывать UI Kit

**Что берём:**
- Аудит тёмной темы (не хватает семантических bg-токенов)
- Проверка типографики под кириллицу
- Аудит motion/easing (нет spring-подобных easing)
- Аудит шкалы теней (в целом хорошая, но можно доработать)
- Предложение: единая стратегия «строгий дорогой минимализм»

### Промпт 2: «Senior Frontend + Арт-директор»
**Фокус:** конкретные визуальные баги на скриншотах
**Сильные стороны:**
- Конкретные баги (аватары, таблицы, select, кнопки)
- Практический подход — «вот это сломано, чини»
- Акцент на пиксель-пёрфект и выравнивание

**Что берём:**
- Аватар: статус-индикатор позиционирование
- Таблица: иконки сортировки, пагинация
- Кнопки: пустые квадраты без иконок (уже исправлено lucide)
- Select: наложение текста (уже исправлено placeholder='')
- Цвет зелёного (НЕАКТУАЛЬНО — у нас синий primary, зеленый только success)

### 🔴 ПРОБЛЕМЫ (найдены в коде)

#### 1. Тёмная тема — неполная (CRITICAL)
```scss
// В тёмной теме НЕТ:
// --color-success-bg, --color-warning-bg, --color-error-bg
// --color-primary-light, --color-primary-subtle (тёмные варианты)
```
**Влияние:** Бейджи, фон ошибок, подсветки — используют светлые значения в тёмной теме.

#### 2. Аватар: :host-context не срабатывает
```scss
:host-context(.p-avatar-large) .kp-avatar__status { ... }
```
**Проблема:** p-avatar НЕ является родителем kp-avatar. :host-context ищет класс на предках host-элемента, но `.p-avatar-large` висит на `<p-avatar>` внутри теневого DOM. Скорее всего, селектор никогда не срабатывает.

**Исправление:** Добавить класс на host через `[styleClass]` в p-avatar и стилизовать от него.

#### 3. Иконки сортировки в таблице — прилипание
```html
<th><span>Заголовок</span><p-sortIcon /></th>
```
**Проблема:** `<p-sortIcon>` рендерит иконку инлайн, нет gap между текстом и иконкой.

**Исправление:** Добавить CSS-отступ между текстом заголовка и sortIcon.

#### 4. Focus-состояния
**Проблема:** Нет кастомных focus-колец. PrimeNG даёт стандартные браузерные outline (синие/чёрные пунктиры в Chrome/FF).
**Исправление:** Добавить глобальный `:focus-visible` стиль с `box-shadow` вместо outline.

#### 5. Error-сообщения: контраст
```scss
--color-error: #dc2626; // red-600, ~4.5:1 на белом — на грани
```
**Проблема:** #dc2626 на белом фоне даёт контраст ~4.6:1 — проходит AA, но близко к границе. На сером фоне может не пройти.

#### 6. Motion — нет spring easing
```scss
--transition-fast: 0.15s ease;
--transition-normal: 0.25s ease;
--transition-slow: 0.35s cubic-bezier(0.4, 0, 0.2, 1);
```
**Проблема:** Кнопки и интерактивные элементы используют `ease` вместо более живого `cubic-bezier`. Нет «отзывчивого» easing для micro-interactions.
**Исправление:** Добавить `--transition-spring: 0.2s cubic-bezier(0.25, 0.8, 0.25, 1.2)` для ховеров/фокусов.

#### 7. UI Kit demo — мёртвые pi-иконки
```html
<kp-button icon="pi pi-check" />           <!-- без lucideIcon -->
<kp-button label="С иконкой" icon="pi pi-search" />  <!-- pi-иконка -->
```
**Проблема:** Демо-страница показывает кнопки с pi-иконками, а не lucide. Это сбивает с толку.
**Исправление:** Обновить демо-страницу на lucide-иконки.

## СТРАТЕГИЯ ВИЗУАЛЬНОГО ОЩУЩЕНИЯ

UI Kit должен вызывать ощущение: **«Строгий, дорогой, инженерный минимализм»**

- Цвета: холодные, приглушённые (blue-primary, slate-границы)
- Типографика: чёткая, Inter, с хорошим breathing room
- Тени: мягкие, многослойные, «парящие» а не «падающие»
- Движение: быстрое, отзывчивое (spring-like)
- Радиусы: сдержанные (6-12px)
- Иконки: Lucide — геометричные, консистентные
