## 3. GIT: СТРАТЕГИЯ ВЕТОК

### Как это работает

Да, git-ветки можно использовать как «шаблонизаторы фич». Вот как:

1. **Ветка = изолированная фича.** Создаёте ветку `feature/table-templates`, в ней живёт вся логика шаблонов таблиц.
2. **Мерж в main.** Когда фича готова — сливаете в main через Pull Request.
3. **Изменения в ветке.** Если нужно изменить шаблон таблиц — переключаетесь на ветку, делаете изменения, мержите обратно.
4. **Перенос в другой проект.** Можно сделать `git format-patch main..feature/table-templates` и применить патч в другом проекте.

### Важные ограничения

- **Ветки не «копируются в другой проект» напрямую** — нужен `git format-patch` или `cherry-pick`
- **Ветки живут в одном репозитории** — для переноса между проектами лучше использовать отдельные репозитории-модули
- **Альтернатива:** монорепозиторий с отдельными папками-фичами (как сейчас) проще для одного проекта

### Рекомендуемые ветки для kppdf-4.0

```
feature/ui-kit           → UI компоненты (kp-*)
feature/auth-system      → Авторизация (JWT, refresh, cookies)
feature/table-templates  → Шаблоны таблиц
feature/admin-layout     → Оболочка (sidebar, topbar, layout)
feature/backend-core     → Бэкенд (Express, CRUD Factory, MongoDB)
```
